# M1 — Core platform (task checklist)

Depends on: M0 complete. Frontend tasks (marked **[B]**) additionally depend on the G0-6b visual-acceptance approval.
Spec: `docs/BUILD_SPEC.md`, `docs/SCREEN_SPECS.md` screens 1, 2, 3, 5. Requirements: M01–M04, FR-EVT-*, FR-IMP-*, FR-SPK-*, FR-ADMIN-001/002, NFR-SEC-02/03.

## Identity, access, audit

- [ ] **M1-1 · Staff authentication (OIDC + MFA)**
  - Real OIDC integration replacing the M0-5 stub; session issuance, idle and absolute timeouts, logout, `GET /auth/session` returning identity plus event roles.
  - Acceptance: an expired session is rejected on every route; MFA-less accounts cannot sign in; session fixation and CSRF covered by tests.
  - Verify: `npm test -w apps/api -- auth` · Requirements: NFR-SEC-02

- [ ] **M1-2 · Event-scoped RBAC and the permission matrix**
  - Encode the role × permission matrix (all eight roles × every action in `SCREEN_SPECS.md`) as data in `packages/domain`; middleware enforces it; a generated regression suite asserts every cell.
  - Acceptance: ≥95 % matrix coverage measured by the suite; a cross-event or cross-client attempt returns 403, is audited and raises the alert hook; the UI-facing `permissions` list in `/auth/session` matches the server's decisions exactly.
  - Verify: `npm run test:invariants -- rls-isolation` and `npm test -w packages/domain -- permissions` · Requirements: NFR-SEC-03, FR-ADMIN-001

- [ ] **M1-3 · Audit hardening**
  - Grant-level append-only enforcement, chain-per-event, `POST /admin/audit:verify`, Object-Lock export job, readable projection for the command-center activity feed.
  - Acceptance: UPDATE/DELETE on `audit_records` fails at the database level for the application role; `:verify` identifies a tampered row's position; the activity projection is role-filtered.
  - Verify: `npm run test:invariants -- audit-chain` · Requirements: FR-ADMIN-002

## Events and schedule

- [ ] **M1-4 · Event CRUD, duplication, branding**
  - `POST/GET/PATCH /events`, `:duplicate` (structure and settings only), holding media and slide-template upload, deadlines, team assignment.
  - Acceptance: duplication copies rooms/tracks/deadlines/templates/team and copies no speakers, files or communications; a `draft` event sends nothing to anyone.
  - Verify: `npm test -w apps/api -- events` · Requirements: FR-EVT-001/002/003

- [ ] **M1-5 · Schedule domain**
  - Rooms, tracks, days, sessions (session/break/panel), slots; moves, cancellations, replacement speakers via the session lifecycle; room profiles (aspect, playback codec) used later by inspection.
  - Acceptance: moving a session re-routes room assignments and marks old room copies obsolete; a replacement speaker inherits the slot and preserves the prior speaker's file history; cancellation removes the slot from room lists without deleting files.
  - Verify: `npm test -w apps/api -- schedule` and `npm run test:scenarios -- replacement-speaker` · Requirements: M03, SRS §18

- [ ] **M1-6 · Schedule import (XLSX/CSV)**
  - Parse, auto-map columns, validate with per-row blocking/warning classification, fuzzy suggestions with apply-fix, error-report CSV, transactional commit.
  - Acceptance: 212-row fixture parses and validates in ≤10 s; a blocking error prevents commit; applying a suggestion edits the staged row only; committing twice from the same import is idempotent.
  - Verify: `npm test -w apps/api -- import` · Requirements: FR-IMP-001

- [ ] **M1-7 · Re-import with diff preview**
  - Match on `(room, start, title)`; produce create/update/unchanged/orphan counts and a reviewable diff; commit updates rather than duplicating.
  - Acceptance: re-importing an unchanged file yields 100 % "unchanged" and zero writes; a changed room on one row updates exactly one session.
  - Verify: `npm test -w apps/api -- reimport` · Requirements: FR-IMP-002

## Speakers

- [ ] **M1-8 · Speaker directory and assignments**
  - CRUD, search (server-side, ≤1 s P95 on 348 records), assignments with roles (speaker/moderator/panelist), notes, accessibility needs, release permissions.
  - Verify: `npm test -w apps/api -- speakers` · Requirements: FR-SPK-001/002

- [ ] **M1-9 · Duplicate detection and merge**
  - Detection on create and import (email exact, then name+organisation fuzzy); `:merge` preserving both histories and all assignments, audited.
  - Acceptance: post-merge there are zero orphaned assignments and both file histories are reachable; merge is idempotent under replay.
  - Verify: `npm test -w apps/api -- speaker-merge` · Requirements: FR-SPK-003
