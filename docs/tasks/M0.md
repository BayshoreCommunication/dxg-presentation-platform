# M0 — Foundation (task checklist)

Status: ready to start. **No gate dependency** — M0 needs neither the visual-acceptance approval nor Windows hardware.
Spec: `docs/BUILD_SPEC.md` §5–§6, §14–§16. Contract for every task: `docs/PLAN.md` "Task contract".

Each task: one bounded behaviour, ≤5 files where practical, tests with or before the code, verification command green, one commit whose body names the requirement IDs.

---

- [ ] **M0-1 · Contracts package**
  - Move `api/openapi.yaml` → `packages/contracts/openapi.yaml`; add `operationId` to every operation; define entity schemas for Event, Room, Session, Slot, Speaker, File, FileVersion, Finding, Comment, RoomFile, Manifest, ArchivePackage, AuditRecord, Error; keep the existing paths.
  - Add `scripts/generateContracts.mjs` (RFPilot pattern) emitting `packages/contracts/generated/*.ts`; `contracts:generate` / `contracts:check`.
  - Acceptance: spectral lint 0 errors; every path has an operationId; `contracts:check` passes on a clean tree and fails after hand-editing a generated file.
  - Verify: `npm run contracts:check && npx spectral lint packages/contracts/openapi.yaml`
  - Files: `packages/contracts/**`, root `package.json`

- [ ] **M0-2 · Workspace scaffolding**
  - npm workspaces per BUILD_SPEC §5: `apps/api`, `apps/worker`, `apps/dispatcher`, `packages/domain`, `packages/db`, `packages/contracts`. (`apps/control-center`, `apps/speaker-portal`, `apps/ui` are **not** scaffolded yet — blocked by G0-6b.)
  - TS project references, `strict: true`, ESLint flat config `--max-warnings=0`, `npm run ci` = contracts:check && lint && type-check && test && build.
  - Acceptance: `npm run ci` green on an empty-but-wired repo; api process starts and serves `/ops/health`.
  - Verify: `npm run ci`
  - Files: root `package.json`, `tsconfig*.json`, `eslint.config.mjs`, `apps/*/src/index.ts`

- [ ] **M0-3 · Database plumbing**
  - Migration runner over the existing `db/migrations/001–005`; `db:migrate`, `db:reset`; RLS session helper (`withScope(tx, {userId, clientId, eventId})` issuing `SET LOCAL`); transactional test harness that rolls back per test; synthetic seed fixtures (one client, one event, 3 rooms, 6 talks — no real content).
  - Acceptance: migrations apply to an empty Postgres 16 and are idempotent on re-run; a query outside the scoped event returns zero rows with RLS on.
  - Verify: `npm run db:reset && npm test -w packages/db`
  - Files: `packages/db/**`, `db/seeds/**`

- [ ] **M0-4 · Domain: transition engine + six lifecycles**
  - Implement `packages/domain`: processing, inspection, review, room-sync, session and archive lifecycles exactly as `docs/WORKFLOW_STATES.md` defines them; a shared `transition()` taking (from, action, actor, reason, override) and returning `Result`; `deriveStatus()` implementing WORKFLOW_STATES §8 (the prototype's `derived()` is the reference).
  - Acceptance: a table-driven test enumerates every (state × action) pair for all six lifecycles and asserts allowed/refused; refusals carry a message naming the current state and the allowed actions; overrides require the right role plus a reason; `deriveStatus` truth table covers all seven priority rules.
  - Verify: `npm test -w packages/domain` (branch coverage of the transition tables = 100 %)
  - Files: `packages/domain/src/**`, `packages/domain/src/**/*.test.ts`
  - Requirements: FR-REV-002, FR-INSP-002, FR-SYNC-001/002, SRS §9

- [ ] **M0-5 · Request spine**
  - Auth stub (session shape only; real OIDC is M1-1), permission middleware reading the role × permission matrix, idempotency store over `idempotency_keys`, outbox write helper, dispatcher process, audit chain append + `/admin/audit:verify`, error taxonomy mapper, SSE endpoint `/events/{id}/stream`.
  - Acceptance: a demo transition endpoint writes row + audit + outbox in one transaction and rolls all three back on failure; replaying an idempotency key returns the stored response without a second transition; a tampered audit row makes `:verify` report the first broken link; a cross-event request returns 403 and writes `security.cross_event_attempt`.
  - Verify: `npm run test:invariants` (I-4, I-5, I-6 green)
  - Files: `apps/api/src/middleware/**`, `apps/api/src/lib/**`, `apps/dispatcher/src/**`, `tests/invariants/*`
  - Requirements: FR-ADMIN-002, NFR-SEC-03

- [ ] **M0-6 · Sync PoC against the real protocol (closes G0-2)**
  - Implement the BUILD_SPEC §10 manifest endpoints plus a headless client with the content-addressed SQLite cache, resumable ranged download, per-chunk and whole-file verification, and an offline log queue with `(agent_id, local_seq)` dedup.
  - Acceptance: 20 runs with induced disconnects → resume success ≥99.5 %, zero checksum mismatches; 1 GB over a 50 Mbps shaped link ≤5 min; manifest P95 <500 ms; 24 h simulated offline log replay produces no duplicates.
  - Verify: `npm run test -w apps/worker -- sync` + evidence table in `docs/poc/SYNC_POC.md`
  - Files: `apps/api/src/routes/agent.ts`, `packages/domain/src/sync/**`, `apps/room-agent/src/sync/**`, `docs/poc/SYNC_POC.md`
  - Requirements: FR-SYNC-001/003, NFR-PERF-02/03, NFR-INT-01

- [ ] **M0-7 · Local stack and CI**
  - Extend `docker-compose.yml` with api/worker/dispatcher; GitHub Actions running `npm run ci`, `test:invariants`, and the migration check on every PR; branch protection on `main`.
  - Acceptance: a PR with a failing invariant cannot merge; `npm run dev` brings the whole stack up from a clean clone in one command.
  - Verify: CI green on a scratch PR
  - Files: `docker-compose.yml`, `.github/workflows/ci.yml`
